# 索引增量/热更新墙钟基准(RUST-102 余项收口,2026-11-15)

PR-005 已立解析基线(P50 6µs/大样本 19.9MB/s/增量二扫零重建);本报告补
**索引层(kode-index)热更新与增量墙钟**——编辑器接入的稳态交互形态数字,
全部 release 实测(禁 debug 结论)。

## 复现

```bash
cargo run -p kode-index --release --example bench_increment
```

车道:①2000 文件首扫全量 ②热更新形态(单文件编辑→增量重建,300 次)③同文本
零重建 ④rename/remove 增量面 ⑤根级失效→全量重扫 ⑥巨型单文件。

## 实测(本机 14 核,release,2026-11-15)

| 面 | 数字 |
| --- | --- |
| 语料 | 2000 文件,12,024,500 bytes(均 6012 B/文件),真实形态实体 def(64 属性+12 方法+继承链) |
| 首扫全量(update_batch) | rebuilds=2000,symbols=154000,gen=1,总耗时 825.0ms,**吞吐 13.9 MB/s** |
| 热更新单文件增量重建 | **P50=402µs / P95=672µs / P99=739µs / max=757µs**(n=295,每次真实改文本必重建) |
| 同文本零重建 | 1000 次 update 全 cache-hit,**9.5µs/次**,generation 不变 |
| rename(50 次 remove+update) | 318µs/次;未注册文件 remove 50 次共 0.0ms(无副作用) |
| 根级失效 | invalidate_root 清 155450 符号 81.5ms → 全量重扫 739.7ms(与首扫 825ms 同路径同量级,无隐藏超线性) |
| 巨型单文件(2 万属性,1.6MB) | 首插 148.1ms / 热更新重解析 169.3ms |

## 解读与边界

- **热更新稳态交互面亚毫秒**:单文件编辑到索引重建完成的墙钟 P50 0.4ms、
  上界 0.76ms——编辑器逐字符输入流下索引重建不是瓶颈面。
- **增量有效性双证**:文本真变必重建(断言 rebuilt)、文本未变必零重建
  (断言 cache-hit 且 generation 不变)——两者同车道互为对照,防假增量。
- **根级失效是线性面**:失效+重扫与首扫同量级(0.9x,差异来自重扫时缓存
  分配更暖),没有超线性回退;invalidate_root 本身(清符号/倒排)80ms 量级。
- **巨型单文件是独立形态**:1.6MB 单文件全量重解析 ~150ms,若高频编辑此类
  文件,增量到行/CST 级(ADR-102 预留的再评估项,触发条件见其「若后续基准
  证明瓶颈按 ADR-002 重评」)才有进一步空间;当前形态下
  该成本与解析层基线一致(19.9MB/s → 1.6MB≈80ms 解析,索引装配另计)。
- ARCH-012 纪律:本车道只立 Rust 自身基线,不做 Rust↔TS 性能对比结论。
- 与解析层基线(P50 6µs)的关系:索引层单文件增量重建(≈400µs)≈ 60+ 文件
  的解析量,大头在符号装配/倒排维护,不在解析——符合预期分层。
