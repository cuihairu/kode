## 4. 全部署确认(重启面)

做法:同一批结构改动改在**启动前**staged(`KBE_DEMO_ASSETS` 指向含全部改动的资产目录),`stop` → `start`(DB 自动重建)→ bots。全程**零 reload**:

- `/status` 双侧 `revision: 0, receipts: []`(空回执=boot-native 的硬证据);
- boot 锚:`Space cell[2002] spawn done: [1..8]`、心跳 tick 1×2 进程、bots 进世界开战(行为行 `Avatar[hot-v3][2014].reqAttack ... dmg=15` 来自 boot 代码);
- console 复测:`createEntity('SurveyDrone', ...)` → **`created at boot: 9`**;活 avatar `demoStructTag` → **`7`**——结构在全部署形态一次成立。

## 5. 「结构变化需重启」实测裁定（诚实口径）

| 变化类别 | 实测 |
|---|---|
| 现存实体脚本逻辑 | reloadScript(单进程)即生效,不需重启(面 3/4) |
| def 属性新增 | 本构建 reloadScript(fullReload) **热接,不需重启**(面 5)——todo 原文预期「需重启」,按实测修正记录 |
| 新增实体类型(def+注册+脚本) | 单进程 reload 后该进程可用(面 6);**未 reload 进程不可用**(面 7 TypeError) |
| 全部署一致 | reloadScript 为 per-app console 通道,逐进程 reload 可达但各进程 revision 独立;**重启一次全部署携带结构成立**(§4,revision 0) |

即:「需重启」在本构建的真域是**未 reload 进程与全部署一致性**,不是「结构变化一律要重启」——后者被面 5/6 实测否定,按纪实落账,不替 todo 原文圆场。
