# ADR-107 — 引擎源码消费:窄面策展(版本标记+符号锚点有界扫描),不做全树自动索引

- 状态:已接受(2026-11-17,RUST-294 裁决落档;窄面策略 de-facto 在役,本 ADR 追认并以全树反事实实测钉预算)
- 关联:书 §18 ADR-107、RUST-294、RUST-174(符号锚点绑定,9a144db2 收官)、C-14(真树双标记探测)、ADR-110(stub 车道,零引擎源读取)、ADR-101(同模式:裁决须实测证据)
- 证据:`crates/kode-python/examples/bench_corpus.rs`(全树反事实臂,本批)+`docs/review/` RUST-174 收官记录(有界扫描 caps)+`tests/engineTreeProbe.test.ts`(探测口径与产品同源)+`KBENGINE_SOURCE_AUDIT_PLAN.md`(引擎树=对照基线 `../kbengine`)

## 背景

书 ADR-107:用户工作区含引擎源码时,metadata 自动索引的范围与成本预算,
允许仅需的 symbols。kode 对引擎树的真实消费(现役三车道,全部窄面):

1. **版本标记**:`engineApiMetadata`(C-14)双标记(version.h/kbeversion.h)
   探测引擎根——只读 2 个标记文件;
2. **策展符号锚点**(RUST-174):把策展 KBE 符号表(`kbeModuleIndex`)
   解析到真实引擎检出——Python=引擎 typings 单文件锚点行复验;
   C++=`kbe/src/lib` 头文件有界扫描(深度≤7/单文件≤20000 行/仅 `.h`/
   目录排序确定性首命中),未见/缺席各自如实分型,绝不编造位置;
3. **stub 车道**(ADR-110):`import KBEngine` 的类型面走内置静态模板,
   完全不读引擎源码。

## 决策

**不做全树自动索引;消费一律走窄面策展车道;「仅需的 symbols」=策展
符号表按需加表项,不加索引器。**

预算依据(全树反事实实测,2026-11-17,本机真引擎树 `../kbengine`,
`bench_corpus` release):

| 口径 | .py 文件 | 字节 | ruff 容错解析墙钟 | 语法错误 |
|---|---:|---:|---:|---:|
| 全树(走读含符号链接目录) | 1776 | 18.5 MiB | 617.6 ms(30.0 MiB/s) | 2 文件/2 处 |
| 源码口径(排除 node_modules/.git/target/vcpkg*) | 1746 | 18.4 MiB | 363.3 ms(50.7 MiB/s) | 2 文件/2 处 |

- 全树自动索引的一次性解析本身虽只 ~0.6s,但其后是**持续的索引面债务**:
  持久化缓存(对照 ADR-103 矩阵,50k 档形态预算完全不匹配)、指纹失效、
  内存驻留、Windows 文件数放大——为实际无消费面的「全量符号」付常驻税。
- 现役窄面车道预算=**每符号一次有界扫描**:Python 单文件读(typings .pyi),
  C++ 上界=`kbe/src/lib` 头文件域(实测 890 个 `.h`/9.0 MiB,深度与行数
  caps 内首命中即停),与全树索引差 ≥3 个数量级,且只在用户显式命令
  (`kbengine.api.engineSource`)或符号解析时付。
- 引擎树实际形态佐证:1.5 GiB 树中真源码 `kbe/`=669 MiB(其余为
  node_modules/vcpkg/构建产物),全树走读口径天然被非源码主导——
  「自动索引范围」若开,必须先付范围裁剪,而裁剪后的真实需求
  (API metadata+引擎源导航)窄面车道已全覆盖。

## 后果

- 正面:零常驻索引税(内存/持久化/失效面);引擎树升级/魔改不影响 kode
  核心索引(锚点缺席只如实降级);预算差 3 个数量级有实测背书。
- 负面/约束:引擎内**非策展符号**无全局导航(如全引擎 C++ call graph/
  任意符号全局跳转不在产品面);锚点行漂移只给文件不给假行(RUST-174
  口径)——诚实但不如全索引覆盖。
- reopen 条款:产品需求出现引擎内非策展符号的全局导航/查询时重评
  (须给出目标符号面与预算实测,不接受「顺手全索引」);引擎树形态
  变化(如官方收缩到纯源码树)时重测全树口径。

## 边界(诚实)

- 实测走读不跳过符号链接目录(`read_dir` 语义),1776 文件为跟随口径
  上界;非符号链接语料 `find`(不跟随)=977 文件——两口径同一决策量级,
  裁决对 2 倍噪声不敏感;
- 墙钟只含 ruff 容错解析,不含符号抽取与持久化(反事实下界口径,
  真实全索引成本更高,只强化本裁决);
- 2 处语法错误文件未逐一定位(计数口径;容错解析不失败,如实记);
- C++ 头文件域统计(890 `.h`/9.0 MiB)为全 `kbe/src` 域,RUST-174 实际
  扫描域为 `kbe/src/lib` 子域(更小,上界口径)。
