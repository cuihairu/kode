## 坐标转换对拍(emoji/CRLF 样例)

样例文本 `text = "👍x\r\nab🎯c"`(字节:`👍`=0..4,`x`=4..5,`\r`=5,`\n`=6,`a`=7,`b`=8,`🎯`=9..13,`c`=13..14)。对拍方法:LineIndex(字节扫描+二分)与朴素参考实现(`split('\n')`+strip 尾 `\r`,零共享代码)对**每个合法 (line, character 0..=行 UTF-16 长)** 与**每个字符边界 byte** 双向全量比对(`tests/coordinates.rs::cross_check`);断言样例(`documented_samples`):

| Position(line,UTF-16 char) | byte 偏移 | UTF-16 全文偏移 | 说明 |
|---|---|---|---|
| (0,0) | 0 | 0 | 行 0 首 |
| (0,1) | 0 | 0 | **👍 代理对中点 → clamp 到字符起点** |
| (0,2) | 4 | 2 | 👍 = 2 UTF-16 unit / 4 bytes |
| (0,3) | 5 | 3 | x 之后 |
| (1,2) | 9 | 7 | 行 1 内容 "ab🎯c" 从字节 7 起(CRLF 的 `\r` 不计入 character) |
| (1,4) | 13 | 9 | 🎯 中点 clamp 不发生(character=4 落在 🎯 之后) |

反查:`position_of(9) == (1,2)`;`utf16_offset_to_byte(5) == 7`(行 0 内容 3 unit + `\r\n` 2 unit);`byte_offset_to_utf16(7) == 5`。
回映不变式(全样例扫描验证):byte→position→byte 恒等,唯一例外是 `\r\n` 的 `\n` ——终止符中点在 LSP 坐标空间不可寻址,回映落在 `\r`(内容末尾)。

## kode-server 对接的行为差异(如实声明)

1. **stale didChange 从「接受」改为「拒绝」**:PR-003 的自造 store 无条件覆盖 version;现在 version 未严格递增的 didChange 被忽略,文本与版本都不回退(ARCH-005 不过期覆盖)。TS client 版本单调递增,现有行为不受影响(e2e 4 用例 + fake server 7 用例全过)。
2. **stale didOpen 被忽略**(LSP 语义:didOpen 只该出现在未打开文档)。
3. **增量 didChange 可用**:capability 仍是 full sync(change=1),但协议 DTO 与 VFS 已支持 ranged change,server 状态机单测覆盖 emoji ranged 编辑。
4. **根归属**:initialize.rootUri 注册为资源根;文档按最长前缀归属根(VFS-009);根外文档归 `RootId::UNROOTED`,与根内同名文件不混淆身份。
5. **URI 规范化**:文档身份从原始字符串变为 canonical URI(`/w//a.def` 与 `file:///w/./a.def` 同一身份)。

## 已知边界(不隐瞒)

- VFS-001 的 Windows UNC/WSL/Unicode normalization/大小写折叠语义是**文档声明**了规则与余项,实现随 PR-006(root discovery)落地;基础版明确不做假装支持。
- VFS-006 指纹是 mtime+size;内容 hash 增强(HR-HASH-001 fileHash)留指纹专项,接口已预留。
- VFS-008 只做路径分类基础版;`.def`/types.xml 等的独立发现规则与引擎版本 profile 随 PR-005/006。
- `DocumentBuffer` 编辑是整段重建行索引(O(n) 每次 didChange),查询路径已免全文 split;真正的增量 rope/增量行索引更新待基准数据(ADR-002)证明必要后再做,不提前优化。
- PH1-03 的「单文件 `.def` Hover/Definition 真实垂直切片」不在本单(VFS 是它的前置),随 PR-010 Provider 接线。
- 未测任何性能对比(ARCH-012)。
