## 对拍 golden 双向门禁

- 正本:`crates/kode-parser/tests/golden/def-parity.json`(由 Rust `dump-golden` 从语料生成,含 20 .def + 4 entities.xml + 3 types.xml + 1 alias.xml)。
- Rust 侧:`tests/fixtures_golden.rs::golden_matches_regenerated_dump` 重生成比对(任何一侧语义变化即刻失配)。
- TS 侧:`tests/kodeParserParity.test.ts` 用 `src/defParser.ts`(vendor fast-xml-parser,现有实现)独立复算同一 golden,**28/28 一致,通过率 100.0%**(golden 的 `syntaxErrorCount` 为 Rust 侧专有字段,比对时跳过)。
- 已知口径差异(如实声明):golden 提取面 = TS 现有实现可表达的语义(名称/类型/旗标/方法/行号);TS fxp 正则定位层在畸形输入上会抛错,而 Rust 侧容错保树 —— golden 语料全部可解析,差异面不在对拍内。

## 已知边界(不隐瞒)

- SEM 全量(类型 IR/内建 API/跨语言导航)不在本单:类型解析只到「引用名收集」,SEM-002..003 的 TypeId/来源 span 结构随 PR-008。
- DEF-016 依赖索引是名字级反向索引,文件级 DAG/SCC(IDX-002/005)随 PR-007。
- golden 对拍覆盖结构语义,不覆盖 hover 文案/诊断文案(QA-003 全量 golden 随 PH2-03 双轨)。
- fuzz纲要有意后置(任务书允许):当前为确定性盲样 1149 例,非 property-based。
- CDATA 内行首 `#` 同样被伪注释掩码(引擎 .def 不使用 CDATA,已文档化于 `mask_def_pseudo_comments`)。
- 未测任何 Rust↔TS 性能对比结论(ARCH-012):bench 只立 Rust 自身基线,替换决策按 ADR-002 随 PR-010 双轨数据。
