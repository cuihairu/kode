## Def & Entity Intelligence

- **kbengine-def language & grammar** — `.def` files get a dedicated language id, bracket rules and a TextMate grammar — (evidence: package.json#contributes.languages, package.json#contributes.grammars)
- **Real-time .def diagnostics** — unknown types / Flags / DetailLevel values, duplicate property & method definitions, missing Type/Flags fields, with a master switch — (evidence: package.json#configuration `kbengine.diagnostics.*`, `kbengine.enableDiagnostics`; src/defAnalyzer.ts)

- **Quick Fix: unknown type correction candidates** — the unregistered-type diagnostic (stable code `kbengine.unknownType`) offers QuickFix replacements drawn from registered types only (builtins + types.xml + entities), case-normalized edit distance ≤ 2, distance-sorted and capped at 5; edits touch only the current document, no declarations are auto-created — (evidence: src/languageProviders.ts `KBEngineTypeCodeActionProvider`, `UNKNOWN_TYPE_DIAGNOSTIC_CODE`)
- **Code Action: generate empty implementation for unimplemented def methods** — acting on a def method declaration whose owner script exists but lacks the method, offers a single Refactor action whose title shows the target file and insertion line; the skeleton is `def name(self, arg0..argN)` with `pass` body, `<Arg>` count driving the parameter list; the insertion point is computed from the target file's current text (open buffer preferred); already-implemented methods (same query face as Go to Implementations) are not offered again — (evidence: src/languageProviders.ts `KBEngineMethodImplementationCodeActionProvider`; src/entityMapping.ts `listOwnerScriptFilesForIdentity`)

- **Project profile identity store** — each KBEngine assets/engine combination is saved as its own profile with a persistent stable ID (assigned once at creation, stored per workspace in `workspaceState` and read back after restart); the display name is only a mutable field — renaming a profile or having two same-named profiles never merges or loses identity; roots are saved per profile (`saveRoots` touches only the target record's path fields, so re-saving one profile's assets/engine roots never bleeds into another and both read back independently after restart) — (evidence: src/projectProfiles.ts `ProjectProfileStore`)
- **Active profile selection** — the active profile is remembered by its stable ID (workspaceState), so renaming never loses the selection; each real switch (new ID ≠ old ID) fires exactly one change event other features can subscribe to, re-picking the same profile fires nothing; an unknown ID is refused and a selection whose record was removed resolves honestly to null — (evidence: package.json#contributes.commands `kbengine.project.selectActive`; src/activeProfile.ts `setActiveProfile`/`onDidChangeActiveProfile`)
- **Profile health summary** — the active profile's health is summarized with four issue kinds (根歧义 assets root gone, 缺引擎 engine root unrecorded/gone, 缺解释器 interpreter unrecorded/gone, 缺语言服务 the PRJ-005 check reporting anything other than active), each carrying its own navigation entry (re-import command / interpreter setting / service-status command); all healthy is a single message, issues open a picker where a picked row jumps to its entry — (evidence: package.json#contributes.commands `kbengine.profile.health`; src/profileHealth.ts `collectProfileHealth`/`showProfileHealthSummary`)
- **Language index follows profile switches** — the active profile's assets root becomes the index input (ahead of the `kbengine.assetsRoot` setting and auto-discovery; a selected root that no longer exists falls through honestly to the normal chain); a switch removes the old external roots from the indexes (the SNP-009 removal path) and advances the root-config generation, so in-flight scan batches started under the old profile write nothing into the current snapshot — the new input is rebuilt by the next scan — (evidence: src/scanRoots.ts `setActiveProfileScanRoot`; src/entityMapping.ts `performScanEntityMappings` generation gate; extension.ts `onDidChangeActiveProfile` wiring)
- **Launch follows the active profile** — the next launch resolves the engine bin from the active profile's engineRoot (`kbe/bin/server` under it) and the config root from its assetsRoot (ahead of the `kbengine.binPath`/`kbengine.assetsRoot` settings and auto-discovery, per field: an empty field falls through honestly to the settings chain; a profile config root is authoritative — no silent fallback to workspace discovery); resolution happens at launch time by stable ID (no cache, so a switch needs no re-wiring), and each registered instance snapshots the bin/config roots and profile ID it actually started with — switching profiles afterwards never touches a running instance's record, pid, or process; a same-key start while registered is still refused (already-running), and the selected profile only takes effect from the next launch — (evidence: src/serverManager.ts `getActiveProfileLaunchRoots`; src/serverManager.ts `RunningServer.binPath`/`configPath`/`profileId`)
- **Existing project import** — pick the assets root and the four faces (entities/defs/scripts/engine) are identified via the shared convention chain, with any face not found previewed honestly as 未识别 (not identified); the preview lists all four results and only picking 导入 creates the profile — Esc or dismissing any step writes nothing, and a folder with no KBEngine structure at all is rejected without a preview — (evidence: package.json#contributes.commands `kbengine.project.import`; src/projectImport.ts `identifyProjectLayout`/`importExistingProject`)
- **Interpreter source per profile** — each profile records which Python interpreter it uses and where it came from (the `kbengine.python.interpreterPath` setting if the file exists, else python3/python located on PATH, else an explicit missing state — never a fabricated path); the import confirmation shows the interpreter state inline, and records saved before this field existed read back as missing rather than being dropped — (evidence: src/profileInterpreter.ts `resolveInterpreterWith`/`describeInterpreterState`; src/projectProfiles.ts `saveInterpreter`)
- **Python language service status check** — reports 未安装/未启用/已激活 for `ms-python.vscode-pylance` from registration + activation + install-directory evidence; an extraPaths write is never counted as availability, only called out with an explicit caveat — (evidence: package.json#contributes.commands `kbengine.python.serviceStatus`; src/pythonLanguageServiceStatus.ts `classifyPythonService`)
- **Minimal project creation template** — a fixed manifest lists every directory and file a new empty KBEngine project needs (relative paths, file contents included, scripts layout aligned with the shared discovery conventions so the skeleton is importable); creation planning probes each target path up front — any existing target is reported as a conflict with its exact path, and the preview lists one row per entry with its exact absolute path — (evidence: src/projectTemplate.ts `MINIMAL_PROJECT_TEMPLATE`/`planProjectCreation`/`buildProjectCreationPreviewItems`); the create command wires the manifest to disk with the full generator protection set — refuse-on-conflict before any preview, the shared generator confirm QuickPick, atomic file writes, and roll-back-everything-this-run on failure, then registers the profile through the same identification chain as the import command — (evidence: package.json#contributes.commands `kbengine.project.create`; src/projectCreate.ts `createMinimalProject`)
