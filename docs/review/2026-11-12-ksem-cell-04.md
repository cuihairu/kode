## 实现

**Rust 面(semantics_rpc.rs 新模块)**:`$/kode/semantics/cellDataKeys`
`{entity, defs:[{name,text}]} → {entity, status, keys:[{key,kind,typeLabel,
sourceFile,sourceLine}]}`:

- 无状态 handler(def 数据流 TS→Rust 按请求供给,与 analyzeDef 同口径,
  引擎不扫盘不缓存);defs 逐个 parse_def 提交 SnapshotStore,`ProjectDefResolver`
  解析出实体 → `CellDataShape::build`(CELL-01/02/03 全语义)+ `key_views()`
  三面投影(defField/builtin/componentSlot,serde camelCase);
- 实体不在供给宇宙 → 响应级 `status="entity-missing"`、keys 空(不冒充
  无部件,与 CellDataStatus 四态分账);参数畸形 → Err 不 panic;
- 接线:lib.rs `pub mod semantics_rpc` + server.rs `register` 双注册;
  测试 4(三面齐全含组件槽类型标签=组件类型名/组件字段不在顶层键宇宙/
  实体缺不造/畸形参数报错)。

**TS 面(backend/cellDataCompletion.ts 新纯模块)**:

- `cellDataKeyCompletionContext`:同行探测 `self.cellData["…"` /
  `self.cellData.get('…'`(开引号+片段;闭引号/闭括号后不接管;非 self
  接收者不接管;片段含反斜杠不接管),替换起点=片段精确区间(不含引号;
  光标紧跟 `[`/引号时为空片段插入位);
- `cellScriptRoleAndEntity`:仅 `scripts/cell|base/<Name>.py`(KR-AUD-74
  布局,反斜杠路径归一);client/bots/其他角色 null(不混入);
- `collectCellDataDefUniverse`:def 宇宙闭包 BFS(Parent/Interfaces/组件
  类型,经 parseDefFileSemantics 出边,与引擎装载口径同源——接口 def 不走
  Parent 边、组件 def 的父也是组件);缺文件/解析失败=该贡献缺席不猜,
  visited 环安全;
- `fetchCellDataKeys`:gate.runInRust 整面形状校验(无 gate/失败/keys 非
  数组/条目缺核心面 → 整面 null,绝不部分采用)。

**接线(languageProviders/completion.ts)**:KBEngineCompletionProvider.
provideCompletionItems 顶部键位派发——键位上下文先于 Rust-first def 链
(键位里 def 链成员补全无效,不混入);`provideCellDataKeyCompletions`:
角色不匹配 null(既有同步链零感知,非键位路径同步返回契约不变);Rust
不可用 → [](键位不给任何项,不造键);键项 kind=builtin → Constant、
defField/componentSlot → Field,detail=`typeLabel · sourceFile:line`,
range=引号内片段精确区间。def 文本注入:findDefinitionFileByCategory(document)
+ fs.readFileSync(读失败=缺席不猜)。
