## 2. 真机验收抓出的四个生产缺陷

单元 mock 结构性抓不住、只有真机全链跑得出来的四个真实缺陷,逐个 root cause+顺修:

### bug-1 线上契约:serde tagged enum 嵌套 kind(五面全死)

`CellDataKeyKind` 带 `#[serde(rename_all="camelCase", tag="kind")]`(crates/kode-server/src/semantics/cell.rs)→ 线上条目形状是 `{"key":"gold","kind":{"kind":"defField"},…}`,TS 侧 `isKeyEntry` 按 `typeof entry.kind === 'string'` 判——**真机上 RPC 成功但校验全拒,五面(补全/错键/写入/hover/inlay)自 CELL-02/03 起在生产静默死亡**,只有 unit mock(编码了 TS 侧扁平形状)的绿在撑门面。顺修:边界统一校验+解包(`fetchCellDataKeys`);4 个测试文件的门 mock 迁线上形状;`bin/kode-server` 陈旧(11-08 构建,无 cellDataKeys 符号)预检拦截并给重编指引。坑:git-ignored 的 bin/ 产物不随 cargo build 自动刷新,须 `cargo build -p kode-server --release && cp target/release/kode-server bin/`。

### bug-2 hover 适配器旁路(两类注记生产全死)

`languageServices.ts` hover 适配器直接调 `provideHoverTimed`,绕过类 `provideHover` 包装——C-23 行为注记与 CELL-14 生命周期注记在真机生产路径全不挂(definition 适配器无此漂移)。顺修:共享入口 `provideHoverWithNotes`,类委托它、适配器走它,计时打点保留。

### bug-3 `vscode.Hover.contents` 数组形状(注记静默丢弃)

bug-2 修复后注记仍不出现:真实 `new vscode.Hover(md).contents` 是**数组** `[md]`,既有单对象 `'value' in contents` 判断静默失败。顺修:数组归一化(数组取 parts[0],单对象原样),重建首段 MarkdownString 拼注记。

### bug-4 cellData 三调度器从不冲刷(编辑期诊断全死)

`retriggerCellDataDiagnosticsForDefChange` 与 python 编辑重排都走 `requestQueued`,但共享冲刷定时器(extension.ts)只 flush 八个既有调度器——**cellDataWrite/WrongKey/Callback 三调度器全仓无任何 `flushQueued()` 调用点**,queued 任务永远滞留;只有打开路径的 `'immediate'` 通道发布过(基线绿的原因)。即:CELL-08/10/12 落地起,python 编辑期三诊断就从不更新;CELL-15 的 def 变更重排同死。与 KODE-AUD-001(进程拓扑调度器只入队不冲刷)同形。顺修:共享定时器补三行 `void cellData*scheduler.flushQueued()`。

**prove-green**:真机套件按上述顺序逐面放行——每修一个 bug,失败点前移一 面(基线诊断→F12→hover→脏相位错键重算),终局 `CELLDATA_RC=0` 七行证据全真。套件本职即「验收真实 Provider 全链」,四缺陷均由它抓住,单元 mock 结构性无法覆盖(它们编码的是实现侧形状而非线上契约)。

## 3. 夹具与真机方法论沉淀

- **世界开闭角色分工**:动态写入(`self.cellData["bonus"]="x"`)在同一文件会把键宇宙打成开放世界(CELL-09/10),未声明键的错键「确认」诊断被正确沉默——夹具按角色分工:base 只读(世界封闭,错键成立)、cell 承载写入(写入类型面的靶点,该面不受世界开闭影响);

## 5. 决策记录

- **验收形态=真机套件而非 unit mock**:条目原文「验收真实 Provider 全链」——mock 编码实现侧形状,结构性抓不住线上契约漂移(bug-1/2/3 均此类);真机套件此后作为 cellData 族的回归门(装台一次,后续批次加 face 即加断言);
- **交付面对账口径**:本族(CELL-01..14)`docs/guide/features.md` en/zh 均无 cellData 段落(grep 双语 0 命中)——族级对账面一直走 todo 勾行+review 纪实(+CELL-13 的 api docs 面),本条保持同口径;features.md 族级缺口在此挂账,是否补族级段落等用户点火;
- **跨根重排是保守正确**:invalidateAll 是全调度器代,跨根文档的下一次自身编辑会多算一次——正确性优先,不做按根精细代;
- **单元 mock 分层**:门 mock(RPC 边界)必须用线上形状(嵌套 kind);纯函数直构 mock 保持解包后形状——两层各有其职,混用即 bug-1 复发温床。
