## 实现

**backend/cellDataWriteCheck.ts(新纯模块,不 import vscode)**——诊断族
先例同款(code 常量 `kbengine.cellDataWriteType` / ENABLED_DEFAULT /
`DiagnosticItem` 纯数据面 / l10nText 消息单一来源):

- **引擎标量表 `SCALAR_FAMILIES`**(datatypes.cpp `DataTypes::initialize`
  注册表,与 kbengineMetadata 同源):UINT8/16/32/64、INT8/16/32/64 带
  BigInt 精确封闭区间(tsconfig target < ES2020 禁 `0n` 字面量,全部
  `BigInt(...)` 构造,64 位界以字符串入参保精度——边界判定无 double 取整
  死区);FLOAT/DOUBLE 数值;STRING/UNICODE 字符串;BLOB 字节流;
  VECTOR2/3/4 定元数数值向量;label 供提示期望段(如
  `UINT16 (int 0..65535)`)。不在表内的类型(PYTHON 与 PY_DICT/PY_TUPLE/
  PY_LIST/ENTITYCALL、ARRAY、FIXED_DICT、types.xml 自定义别名)结构未知
  → 不查(诚实);
- **`classifyCellDataWriteValue(text)`**:RHS 整段恰为一个字面量才给类,
  残缺/尾随表达式/名字/调用 → `unknown` 不猜。十进制/0x/0o/0b 整数以
  BigInt 精确解析(下划线剔除);浮点正则分数部分可缺(`10.` 合法);
  字符串/字节串前缀(`r/u/b/f` 组合)识别,引号闭后必须收尾(拼接/属性
  访问 → unknown);`[...]`/`(...)` 序列:三引号/转义/嵌套括号引号感知的
  配对扫描,闭合后必须收尾;`(5)` 是括号表达式不是元组、`(5,)` 才是单
  元素元组、`()` 空元组;`{}` 空 dict,顶层冒号(引号/深度感知)分 dict
  与 set;元素含 unknown 只保元数(elements=null);
- **`checkWriteAgainstFamily(literal, family)`**:unknown 一律 null(测试
  抓出的真缺陷:compute()/hpConfig/未闭合列表曾误报 actual='unknown' 的
  错配——修后未知不猜);integer 族:int/bool 入(bool 是 int 子类),整
  数面按 BigInt 区间判 range;float 字面量入整数族报 structure;float 族:
  int/bool/float 入;str 族:str 入;bytes 族:bytes 入;vector 族:非序
  列报;元数不符报 `list of 2`;元数相符时元素全数值字面量不报、元素是
  其他字面量(字符串/None/dict)报 `list with str component`、elements
  null 不猜;
- **`analyzeCellDataFieldWrites(text, entries)`**:写点/别名/常量键全部
  复用 CELL-06/07 同一面(`scanCellDataKeyOperations` + `cellDataAliasNames`
  + `cellDataAliasState`);只查 `write`(增强赋值/`.get`/del 不参与);
  别名逃逸不作写型豁免(逃逸只降读点存在性,字典形状不变),重绑定后的
  别名写的是别的字典 → 不查;键须在 CELL-04 宇宙且有 typeLabel 且在标量
  表;RHS 经剥行尾注释后从 op.exprEnd 锚定的 `=` 取整段,落点锚 RHS 值;
  消息含实际/期望类型及声明来源(`Avatar.def:5` 行号段,内建只给文件段);
- **消息模板**:`renderCellDataWriteStructureMessage` / `renderCellDataWriteRangeMessage`
  l10nText 单一来源,en/zh bundle 键集全等(646→648)。
