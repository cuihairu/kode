机制(与既有 --manifestnls/--manifestfallback 同族,KODE-I18N-001/003):
runner 把扩展复制到临时目录,**连 l10n/ 运行时 bundle 目录一起复制**,
删掉 zh-cn 运行时 bundle 的一个键(受害键=工作台选择器占位

以 `--locale=zh-cn` 两段启动(第一段注册语言包,第二段 NLS 真正以
zh-cn 起宿主;verify 段 locale 未生效直接红,防「两段都 skip 也全绿」
假阳性),suite 只跑 manifestResolved(三条:① %key% 无残留、②
manifest 缺 key 回落=默认包文案、③ 运行时 bundle 缺 key 回落=英文源串)。

**断言面=被测扩展自注册的探针命令 `kbengine.l10nProbe`**(不在
contributes=不出命令面板,只注册进 context.subscriptions):verify 段

1. `extension.extensionPath === 临时副本`(加载的确实是删键副本);
2. 受害键取词=英文源串(回落语义:不是 zh 译文、不是 undefined、不是空串);

### 工程纪实(两次实跑证伪一条路线)

- 首选路线「套件也搬进临时副本装载(extensionTestsPath 指向副本
  out/,import 的 nlsRuntime 归属被测扩展)」实跑两轮均红于
  `Cannot find module 'glob'`:副本放 /tmp 加 node_modules 符号链接红;
  副本改放仓库内 .vscode-test/(父链自然命中仓库 node_modules,plain
  Node require.resolve 实测可解析)仍红。定位=VS Code 1.141 扩展宿主的
  定制模块解析器对「被测扩展根内」装载的模块做 realpath 收纳检查,依赖
  解析结果落在扩展根外(仓库 node_modules)即拒收;仓库 out/ 装载点走
  defer 分支=普通 Node 解析(② 模式既有布局)。结论:套件搬副本被宿主
  安全模型结构性封死,改探针命令路线(断言面进扩展上下文,套件留仓库 out)。
