### 2.5 证据边界与未测口径(IDE-REV-038 修正)

「超阈值解析不在宿主主线程」只对**异步共享解析面**成立,存在两处已知漏口,本页不再以「超阈值解析已退出宿主」作无条件口径:

1. **同步面 syncDocumentParse 漏口**(src/pythonClassIndex.ts:1188):syncDocumentParse 仍是同步整文件解析 API——同版本命中直取缓存,未命中在宿主内联 `parsePythonFile(document.getText())`,**不按阈值分流**。REV-009 已把生产异步入口改走 asyncDocumentParse,生产 src 无 syncDocumentParse 调用点(仅测试与跨面同对象共享引用),同步面保留作口径不变的旁路;但其存在使「超阈值解析不在主线程」对同步面**不成立**——任何同步消费者再次调用它,超阈值文件将重新阻塞宿主主线程。
2. **首次 hover 同步提取漏口**(REV-035/036 实测):大当前文档(>256KiB)冷开后首 hover,首查只读已发布桶如实未命中,但窗内最大宿主阻塞 21.807ms(样本 120,REV-036 四段法修正值);同面发布排干后 hover 8.479ms(样本 142)、编辑后立即 hover 20.087ms(样本 15,样本偏少)。首 hover 21.807ms 的**归因未隔离**(同步提取/commit/派发叠加),按本页口径**标未测**——不据此单独判定迁移,亦不据此声称解析已全部退出宿主。
3. **已测与未测的边界**:已测面=合成语料三档编辑探针(进程内直测)+真机 ACC-001/002 交互面+REV-035 大当前文档三态 hover(首查/发布后/编辑后立即);未测面=真实项目常态编辑超阈值大当前文档的持续负载、worker 队列积压下的编辑响应、首 hover 宿主阻塞的逐段归因——均标未测,复评触发 §4.3/§4.4 覆盖。

## 3. 判定

**暂缓,不推进 Rust Python 解析原型。** 理由:

1. **交互面不痛**:hover/注解查询实付 1–9ms(真机),解析不落在请求路径上(HOV-010 快照级联)。
2. **编辑面主线程已被结构卸载(异步共享解析面)**:超阈值(256KiB)文件解析派发 worker 线程,主线程实付 commit 段 4–10ms;次阈值常见体量文件解析 p50 0.7–21ms,单次编辑一次性成本,处于或低于可感知门槛——该卸载不覆盖 §2.5 同步面与首次 hover 提取两处漏口(归因未隔离,标未测)。
3. **解析不是用户可感知主要成本**:三档语料中 parse 占编辑面 CPU 的大头(S 87%、M 98%、L 98%),但用户感知通道(主线程阻塞、请求延迟)都已被 worker 派发与快照级联截住——「CPU 占比高」不等于「用户可感知瓶颈」。
4. **Rust 侧无从复用**:R2 索引无任何 Python 语义(r2-index-inventory §4【缺失】),原型是净新建解析器而非迁移;def/XML 侧 6.7×–11.9× 优势(head2head)属已完成的 R1,不构成 Python 侧证据。
5. **无已归因的反向数据**:修复后未见归因到解析的用户可感知卡顿样本(S4 尾值不可归因、样本不足);REV-035/036 首 hover 宿主阻塞 21.807ms 属未归因样本,标未测——本轮反例不直接决定迁移,暂缓/推进只按归因后的真实成本判断。

## 4. 复评触发(任一成立即重开)

1. **真机遥测证伪**:languageServiceMetrics 聚合(现 14 类事件)在真实使用中出现次阈值文件的 document-parse p95 持续 >50ms(主线程可感知)。
2. **worker 通道失效场景**:worker 不可用回退同步解析(阈值检查失效/线程崩溃回退)成为常态路径,超阈值文件重新阻塞主线程。
3. **编辑负载画像变化**:用户真实项目常态编辑超阈值文件且 commit 段(p50 4.2ms)随语义增量化之外的索引增长越出预算(如 >30ms)。
4. **首 hover 同步提取归因**:§2.5 首 hover 宿主阻塞(21.807ms,样本120)经归因后证为同步提取,且随真实项目大当前文档常态编辑出现并越出可感知门槛。
