# KSEM-CELL-07:传播字典别名 —— 纪实(2026-11-12)

账本:`todo.md` KSEM-CELL-07;CELL-06 收口后逐项。验收:支持
`data=self.cellData` 及可确定常量键;重新绑定和动态逃逸后降低确定性。

## 实现

**cellDataReadType.ts(CELL-07 扩展)**——别名流与常量键两组纯函数,消费面
仍是 typeInlayHints 的 cellData 读取提示:

- `cellDataAliasNames(text)`:全文 `NAME = self.cellData`(剥行尾注释;赋值
  前缀须词法代码域,docstring 伪赋值不算)的 NAME 集合,按出现序;`self`
  不作别名;增强赋值/元组目标不匹配;
- `cellDataAliasState(text, name, targetLine)` → `{valid, escaped,
  escapedLine, aliasLine}`:最近赋值(作用域限,与写点同口径)非
  `= self.cellData`(含 for/with-as/增强/海象重绑定形态)→ 无效;别名段内
  名字出现在非 cellData 操作位 → 逃逸(传参/return/属性存/非 get 方法调用/
  容器字面量);`NAME[...]`/`NAME.get(...)` 与裸局部整体引用(`b = NAME`)
  不算;def/class 体内出现不算(未被调用即未逃逸);字符串/注释内出现不算;
- `resolveCellDataConstantKey(text, rawKey, line)`:字符串字面量直解;标识符
  → 最近赋值 RHS 为字符串字面量 → 解引;重绑定(值未知)/非字面量 RHS/
  找不到赋值/非标识符(拼接/f-string/数字)→ null(推不出,不硬猜);
- `scanCellDataKeyOperations(text, receiverNames?)`:缺省只扫
  `self.cellData`;传别名候选后透过别名的同形访问一并入列(op 增
  `receiver` 字段),常量键就地解析,推不出该操作不入列;多接收者合并后按
  (行, 列) 恢复文档序;
- `cellDataKeyProvablyPresent(…, escape?)`:同一键最近**有效**写/删定状态;
  透过无效别名的写/删不算证据继续向早找;逃逸晚于最近写/删(或无写/删)→
  存在性不再可证(get 降可空,下标型不变);逃逸早于写 → 写恢复必有。

**cellDataKeyAccess.ts(增补)**:`ParsedKeyAccess` 增 `rawKey`/`keyLiteral`
(非常量键不再返回 null,空段/未闭合仍 null),`scanCellDataKeyAccesses`
只收 `key !== null`(CELL-05 跳转/引用面零变化——别名访问不入 CELL-05
索引,测试钉死)。

**inlay 接线(typeInlayHints.ts)**:`collectCellDataReadHints` 每读点别名
接收者先核定 `cellDataAliasState`:无效 → 不出;有效且逃逸 → escape 传入
存在性(get 可空)。别名读与直读同键宇宙、同落点规则(cellDataHintPosition
对 `x = data["hp"]` 纯 RHS 同样落目标变量后)。

## 验收(CELL-07 两点全)

| 验收点 | 测试 |
| --- | --- |
| 支持 data=self.cellData | 纯模块:aliasNames/aliasState/scan 带接收者/存在性 4 组;provider:`x = data["hp"]` → `: int`、逃逸后 get → `int \| None`(下标仍 `int`)、有效别名写恢复必有、无效别名写不作证据 |
| 可确定常量键 | `k = "hp"` 后 `self.cellData[k]` → `: int`;`del self.cellData[k]` 后 `get(k)` → `int \| None`;for 目标/增强/非字面量 RHS → 不入列 |
| 重新绑定后降低确定性 | `data = {}`/`for data in`/`with..as`/增强/海象 → 别名无效,读点不出提示 |
| 动态逃逸后降低确定性 | `submit(data)`/`return data`/`self.cache = data`/`data.clear()` → get 降 `int \| None`;逃逸后再写恢复必有;写后逃逸仍降 |

测试 31 例新增(cellDataReadType.test.ts 28 → 59:纯模块 21 + provider
全链 10);CELL-05/06 既有 48 例保绿。诚实边界:别名的别名(`b = a`)不
传播;拼接/f-string/数字键推不出不出提示;无效别名的写/删不算存在性证据。

## 坑

1. **逃逸走查 def/class 闸初版按「比别名更深」判**:`indent > aliasIndent`
   才启动体内跳过——模块级别名(`data = self.cellData` 缩进 0)遇到同级
   `def foo():`(缩进 0)不跳体,方法体内嵌 `def inner():`(缩进 == 别名
   缩进 4)同样不跳,体内 `submit(data)` 被误判逃逸;改与写点作用域口径
   对称:**任何** def/class 头行起体内跳过(缩进回落即出),方法体 case
   测试抓出。
2. **布尔别名收窄不动可空性**:`parsed.keyLiteral`(boolean)不足以收窄
   `parsed.key: string | null` → TS2322;须显式 `parsed.key !== null`
   (cellDataKeyAccessAtPosition 与 scanCellDataKeyAccesses 两处)。
3. **纯函数 escape 是调用方入参**:`cellDataKeyProvablyPresent` 不自行核定
   别名逃逸——provider 先 `cellDataAliasState` 再传 `{line}`;纯模块测试
   若漏传则「逃逸压旧写」恒绿成假阴性,测试须同参先行断言 escaped。
4. **旧 CELL-06 测试契约随签名升级**:op 工厂补 `receiver:
   'self.cellData'`、`cellDataKeyProvablyPresent` 行数组入参改全文 text
   (新模块 docFacesOf 吃 string)——findNearestKeyMutation 需全文做掩码
   与作用域走查。
