# Kode 易用性审查（2026-11-08）

## 审查范围与判断

目标是让第一次使用 Kode 的开发者能打开项目、理解当前状态并完成常见操作。查看了扩展清单、视图注册、快速执行、工作台、数据库/克隆和监控面板的源码。清单共有 139 个命令、130 个配置属性、11 个侧栏视图声明，其中 3 个视图通过上下文条件控制；这些数字不意味着每次都同时显示全部内容。

本次没有可用桌面显示会话，未执行真实 VS Code 界面走查、屏幕阅读器测试或用户访谈。下面是基于源码的可复现路径和风险，不是用户实验结果。静态检测器对监控面板提示一处装饰性边框；这不足以证明易用性问题，未计入优先级。

核心判断：Kode 已有许多单独功能，但没有把「打开项目 → 确认识别 → 启动/连接 → 找到目标 → 查看结果」组织成清晰的任务路径。优先做任务入口和可恢复状态，再调整外观；高级能力仍需能找到。

## 发现

### P0 密码输入未遮挡

`src/playerDataCloneCommands.ts:165` 配置源库/目标库时直接使用 `showInputBox({ prompt })`；依赖接口 `:56` 不包含 `password`，而 `src/databaseWiring.ts:585` 原样传给 VS Code。密码输入时会以普通文本显示，SecretStorage 只保护保存方式，不遮挡输入。

修复：传递 `password: true`，两种连接均覆盖；验证输入框选项及取消/保存行为。不要在测试日志或提示中打印密码。

### P1 首次打开缺一条可执行的主路径

`package.json:313` 起并列注册快速执行、服务器、组件、玩家数据、远程服务器、实体、调试、配置等视图，`contributes` 中未见 `viewsWelcome` 或 walkthrough。`src/startupViewPlaceholders.ts:39` 启动占位返回空数组，初始化期间缺少加载或失败提示。用户看到的各块可能为空，却不能从这一位置判断是未识别、正在加载还是失败。

建议：提供一个轻量「开始」入口，按项目识别、配置/环境检查、打开实体、运行或连接的顺序显示下一步；区分扫描中、无项目、识别失败、就绪，并提供可执行操作。保留原有视图和命令；不要把仅静态列表当作引导完成。冷启动和失败状态需真实验证。

### P1 入口按实现分类，缺少用户目标

`src/activate/monitoring.ts:163` 的工作台一次提供 12 个英文条目，混合发现、诊断、监控、SDK 和数据库操作，只有名称，没有任务说明；139 个命令和 130 个配置项进一步增加搜索成本。该路径中的工作台条目没有使用中文翻译，中文用户仍看到 Discovery & Positioning、Database Drift 等名称。

建议：按「打开/配置项目、启动与调试、查看玩家数据、分析协议」组织常用入口，每项说明作用和前提；中文界面使用中文，术语可在说明中保留英文。其他功能经“更多工具”或原有命令查找；不要删除快捷命令。

### P1 空状态提示与实际点击行为不一致

`src/quickActionTree.ts:39` 的空行提示配置 `.kbengine/debug.json`，但点击实际执行 `kbengine.quickActions.scanScripts`；`src/quickActions.ts:406` 的扫描只找 `.bat/.ps1`，未找到时给出无脚本提示。用户想配置 HTTP 请求时，点击提示不会打开配置入口。

建议：分开提供「扫描已有脚本」和「添加 HTTP 请求/打开配置」，清楚说明扫描会修改什么、未发现脚本如何继续；用实际点击路径验收。

### P1 玩家数据操作断裂且前置条件出现过晚

只读玩家数据视图 `src/playerDataPanel.ts:41` 缺配置时显示引擎配置路径和 assetsRoot/binPath 提示，没有对应修复命令。克隆是另外一组 `kbengine.clone.*` 命令；`src/playerDataCloneCommands.ts:281` 先让用户选择实体、输入 DBID，随后 `:297` 才检查源连接。未配置时用户已经填写的信息无法自动用于完成配置后的重试。

建议：提供一个任务入口，清楚区分只读查询、导出、导入；先检查并引导配置源/目标连接，再收集实体和 DBID；各项提供连接测试、下一步、取消及成功结果。沿用只读查询与写入导入之间的权限边界，以及现有导入预演、目标限制和确认。

### P1 克隆连接配置步骤多，难以纠错

`src/playerDataCloneCommands.ts:150` 起依次弹出主机、端口、用户名、密码、数据库，目标库再选环境。没有步骤数、返回修改前一项或统一核对页面；端口校验只检查数字，超范围值可能直到连接时才报错。任一步取消都会退出本次收集。

建议：提供可返回的分步表单或集中配置面，保留默认端口、输入校验和密码遮挡；提交前展示不含密码的连接摘要并提供「测试连接」。不改变 SecretStorage 存储边界。

### P2 监控工具栏缺少字段名称和无障碍名称

`src/monitoringWebViewHtml.ts:500` 至 `:530` 在一行放置组件筛选、诊断筛选、关键词、刷新间隔、历史窗口和三个按钮；四个 `select` 与关键词输入没有关联 `label` 或 `aria-label`。特别是 `1/2/5/10 秒` 需要用户推断其用途，辅助技术也难以识别控件含义。

建议：为每个控件提供可见标签和程序化名称；保留筛选、暂停和导出的能力，次要频率/窗口放在独立区域。需在窄侧栏、键盘和屏幕阅读器中实际验收。

### P2 状态反馈与恢复入口分散

`src/activate/serverControls.ts:152` 的只读面板刷新、测试连接、按 DBID 查询分别由标题按钮/输入框/通知完成；查询结果以通知消息返回。`src/playerDataPanel.ts:41` 的未配置提示没有一键定位配置。`src/quickActions.ts:434`、`:439` 可能连续发出配置无效和警告通知。一次任务的状态和下一步不集中，用户离开通知后不易回顾。

建议：在任务面保留上次操作、结果时间和可执行的下一步；配置缺失时给出「检查项目设置」入口。保留日志用于诊断，用户界面先显示可理解的原因，不伪称失败必定由某个配置造成。

## 推荐实施顺序

1. 密码遮挡，独立修复。
2. 统一首次打开的项目状态与下一步入口；区分加载/失败/空状态。
3. 修复快速执行的空状态与点击不一致。
4. 打通玩家数据查询与克隆的前置检查和向导，保持只读/写入边界。
5. 工作台任务分组与中文文案。
6. 监控控件标签、键盘访问及小宽度布局；对全套界面做真实 VS Code 验收。

验收建议：用空工作区、有效项目、缺配置、后端不可用四种状态，在 Windows/macOS/Linux 至少各做一次真实安装包走查；记录首次完成项目识别、查看实体、只读查询及失败恢复的实际步骤、耗时、困惑点。时间指标需先建立基线，不从源码审查推断用户耗时。
