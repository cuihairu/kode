# 首次使用入口盘点

这份记录用于 UX-REVIEW-002，不代表首次使用引导已经实现。

| 用户目标 | 现有入口 | 实际行为与限制 |
|---|---|---|
| 打开项目 | VS Code 自带打开文件夹 | 扩展在未打开工作区时仍可激活；不得因视图为空声称项目已识别 |
| 导入已有项目 | `kbengine.project.import` | 弹出目录选择、识别资产结构并预览，确认后建立 profile；它不会替用户打开工作区。取消不写入；目录缺少相关结构时提示未识别 |
| 创建项目 | `kbengine.project.create` | 走现有项目创建流程，成功后建立 profile；应复用既有冲突与取消处理 |
| 查看实体 | `kbengine.refreshExplorer` / 实体侧栏 | 复用实体树与工作区索引；树暂空不等于项目不存在，首次扫描完成前不可显示“已就绪” |
| 检查定义 | `kbengine.project.doctor` | 优先当前 `.def`，否则跨根找第一个 `.def`；缺文件或目录布局不符合时不能作为项目已就绪的依据 |
| 发现与定位报告 | `kbengine.discovery.report` | 输出诊断报告；命令调用时读取当前首个工作区，激活期旧扫描不会在首根切换后覆盖报告；多根选择尚待处理 |

`identifyProjectLayout` 使用约定目录做探测；`workspaceDiscovery` 同时支持外部根和多个候选，前者的结果不能替代后者的歧义/错误处理。`EntityMappingManager.isInitialScanComplete()` 只表明索引首扫成功，不表达“没有项目”、读取失败或当前工作区身份。`runWorkspaceDiscovery` 可能提示用户选择候选，不能直接当成纯读取状态查询。

后续状态实现应以当前工作区和实际异步扫描结果为输入：区分无工作区、进行中、未找到、读取失败与就绪，并给每次工作区变更生成新的请求身份。旧请求结束后不得覆盖新工作区。多工作区需要让用户明确选择目标或显示各根状态，不能擅自把首根结果当作全部项目的结果。
