## 0. 引擎事实（baseapp/entity.cpp，本机检出 `3082ab5`）

### 0.1 触发链（写库前，非写库完成）

| 步骤 | 位置 |
|---|---|
| 归档定时器 / 脚本 `writeToDB()` 入口 | `archiver.cpp:59`；方法表 `entity.cpp:626` |
| 无 cell：直接 `onCellWriteToDBCompleted` | `:1225` |
| 有 cell：发 `reqWriteToDBFromBaseapp` 给 cellapp | `:1229-1236` |
| cellapp：脚本 `onWriteToDB()`（**0 参**，活实体存前钩子）→ `backupCellData()` → 通知 baseapp | `cellapp/entity.cpp:1238-1239`；cellapp 分发 `:1255-1262` |
| baseapp `onCellWriteToDBCompleted`：`onPreArchive` → **脚本 `onWriteToDB(cd)`** → 序列化送 dbmgr | `:1295-1298`/`:1305`/`:1329` |
| 序列化去重：与上次逐字节相同则整个写库跳过、用户 callback 不触发 | `persistentDigest_` `:1353` |
| 写库完成回调（`writeToDB(callback)` 的 callback） | `onWriteToDBCallback` `:1239-1289` |

结论：base 侧脚本是**入库前最后变更点**——回调内改写 `cellData[键]` 直接进紧随其后的序列化流；既有文档「即将写入数据库时触发」的时序是对的，但「将入库的 dict」的绑定面与可空条件错。

### 0.2 参数绑定与可空条件

- 分发处一行定绑定：`cd = cellDataDict_; if (!cd) cd = Py_None;`（`:1401-1403`）——参数是 **baseapp 内部快照 dict `cellDataDict_`**（`entity.h:276`），不是 `self.cellData` 属性；
- 可空条件：`None` ⟺ `cellDataDict_` 从未创建 ⟺ 脚本模块无 cell 面（`createCellData` `:250` 在 `hasCell` 假时早退；有 cell 面则构造路径 `:71` 即建空 dict 并填默认值+`position`/`direction` 三元组 `:284`/`:307-308`，此后永不为 None）；
- 快照语义：内容是**最后一次备份回写**（`onBackupCellData` isDirty `:1108-1123`）或构造默认值——不是 cellapp 活值；有活 cell 时入库数据在 cellapp 侧序列化，快照兜的是 base 侧无 cell 写库面（`addPersistentsDataToStream` 优先 `cellDataDict_` `:431-433`，回落 `__dict__`，再回落默认值+告警 `:523`）。

### 0.3 与 self.cellData 属性可见性的区分

`onGetCell` 的 `destroyCellData()`（`:1024`）删的是**属性**，dict 内部保留（`:562-563` 注释「继续保留，以供备份时使用，这里仅仅让脚本层无法访问到即可」）；属性重建仅构造与备份回写 isDirty 分支。故 onWriteToDB 回调里**参数在场 ≠ `self.cellData` 属性在场**（base 侧此刻属性通常已删——CELL-12 已证）；组件经 `CALL_ENTITY_AND_COMPONENTS_METHOD` 同收本回调，组件对象从来没有 cellData 属性。

### 0.4 双签名陷阱（同名回调两进程不同形）

同一实体类两进程共用：cellapp 侧 0 参（`cellapp/entity.cpp:1255-1262`）、base 侧 1 参（`"O"` 格式 `:1405`）。`def onWriteToDB(self, cellData)` 在 cellapp 侧抛 TypeError——签名须 `cellData=None` 默认值两头兼容。再调 `writeToDB` 递归：`DBID_ > 0` 时 `isArchiveing_` 在回调后即复位（`:1310-1311`），回调内无条件再写即无限循环（既有文档断言保留，源码口径补齐）。
