## 0. 为什么 onGetCell 是唯一确定窗口

诊断的风险面只有误报（合法代码上喊狼来了）。cellData 在 base 侧的生命周期事实（`baseapp/entity.cpp`）：

| 事实 | 位置 |
|---|---|
| `onGetCell` 先 `destroyCellData()` 删属性，再调脚本回调 | `:1024`（`PyObject_DelAttrString` :564；回调 :1030-1032） |
| 恢复路径 `inRestore_` 跳过脚本 onGetCell | `:1030` |
| cellData 无类型级 getter，纯实例属性 | `installCellDataAttr` :217/:238 |
| 引擎侧重建只有构造路径与备份回写 | 构造 :252；`onBackupCellData` isDirty :1122 |
| `onLoseCell` 从不触碰 cellData | `:1052` |

由此推出确定窗口的**封闭性论证**：进入 onGetCell 时属性必已删；脚本执行单线程——方法内普通赋值是唯一能在读取前重建属性的途径；异步备份回写（:1122）不能插进正在执行的方法体中间。**出了 onGetCell 这套论证即刻失效**：onLoseCell/onRestore/onTimer 等回调里属性在不在，取决于引擎内部时机与此前执行路径，静态分析无法排除——按验收第二句「未知调用时机不做确定结论」，一律沉默。CELL-10 已把「声明键被删后读」的成因让渡给本面（其决策表注记），本批兑现。

## 1. 两态流判定（`src/backend/cellDataCallbackCheck.ts`）

纯模块（无 vscode 依赖），对每个 onGetCell 方法体（缩进定界跨度）做 absent/present 两态流：

| 语句形态 | 判定 | 依据 |
|---|---|---|
| 深度 0 `=` 普通赋值（`self.cellData = ...`，含链式/元组解包目标位） | **present**（重建属性） | 属性存储恢复；排除 `==`/`<=`/`>=`/`!=`（下一字符）、增强赋值/walrus（前一字符在 `=+-*/%<>&\|^:!` 且非空） |
| `del self.cellData` | 先按缺失态报（若缺失），再转 **absent** | `PyObject_DelAttrString` 同款删除 |
| 缺失态下任何读取：裸属性读、下标写（`cellData[k]=v` 是读键再赋）、`.get`、迭代、别名 | 报 `kbengine.cellDataLifecycle` Warning | 引擎已在回调前删属性，读必抛 `AttributeError` |

- 存后读静默；存→删→读在读取处再报（del 重置状态）；
- 下标读判据：token 与 `=` 之间深度 0 出现 `[` 即为读（`cellData["k"]=1` 报读不误判写）；
- 注释/字符串掩码后判定（`pythonCodeLines` 同款保位掩码）；闭包/推导式在方法体跨度内照扫；
- 消息引引擎行为（「baseapp/entity.cpp:1024 在脚本回调 :1030 之前删除」）；读取面文案另附可执行出路：「需要的数据请在请求 cell 前存入 base 自有属性」。

## 2. 范围闸

- **角色**：`roles: 'base'`——`cellScriptRoleAndEntity` 判非 base（cell 脚本/普通类/缺角色）即零发现。cellapp 侧无 onGetCell 也无 cellData；组件（entity_component）脚本不报——引擎经 `convertDictDataToEntityComponent`（entity_component.cpp:1461）给组件填 dict，**从不挂 cellData 属性**；
- **模块级 onGetCell**（类外同名函数）不分析——不是引擎回调面；
- **其余回调**（onLoseCell/onRestore/任意方法）一律不分析（§0 封闭性论证不成立）。
