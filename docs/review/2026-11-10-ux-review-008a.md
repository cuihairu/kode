# UX-REVIEW-008a 实现报告(玩家查询/连接检查状态保留)2026-11-10

## 项面

为玩家查询与连接检查保留可回看的最近一次状态、结果时间和结果入口;
结果区分未运行、进行中、空结果、成功、失败与已取消。

## 改动面

**新增纯状态模块 `src/backend/playerTaskStatus.ts`(零 vscode,后端抽取
车道同式)**:
- 六态枚举 `not-run/running/empty/success/failed/cancelled` +
  中文标签表(未运行/进行中/空结果/成功/失败/已取消);
- `PlayerTaskStatusStore`:每任务(查询/连接检查)各保留最近一条,
  `begin`(进行中)→`finish`(终态,带结果时间与结果入口命令 id);
  单调 attempts 序号为 008c(过期异步结果守卫)预留;
- `formatPlayerTaskTime`(本地时区 YYYY-MM-DD HH:mm:ss,格式钉死);
- 结果入口常量 `PLAYER_TASK_RESULT_COMMAND='kbengine.playerData.showResult'`。

**playerDataPanel.ts**:
- 结构化运行器 `runPlayerConnectionTest`/`runPlayerQueryByDbid` 返回
  `{message, outcome}`;原字符串入口 `testPlayerDatabaseConnection`/
  `queryPlayerByDbid` 保留为薄包装(cloneBoundaryRegression 源锁与
  既有覆盖测试零破坏)。预检拒绝(无配置段/RSA 密文不可读)如实记
  failed,精确原因进摘要;
- 查询区分 `empty`(0 行)与 `success`(N 行)——此前仅文案区分,
  现为结构化结果态;
- 连接检查结果行(带时间戳)落「KBEngine 玩家数据(只读)」输出通道
  ——此前只有信息消息一闪而过,现在可回看;
- `buildPlayerTaskStatusNodes`:树顶新增「玩家查询/连接检查」状态两行
  ——终态带结果时间+结果入口(点击开通道),未运行/进行中无入口
  (不造不可执行按钮,004a 同口径);模块级单例 store 供命令与树共用。

**serverControls.ts 命令接线**:
- `testConnection`/`queryByDbid`:过闸/触发即 `begin`(进行中,面板
  即时刷新可见),终态 `finish` 后再刷新;输入取消/空串 = `cancelled`
  (与未运行区分,零消息行为不变);
- 新命令 `kbengine.playerData.showResult` = 结果入口(打开输出通道),
  package.json contributes + activation event + nls 标题(en/zh)齐;
  commands.md en+zh 同步入账(docsCommands 活文档锁测试放行)。
