## 1. 三条泛化结论逐条纠正

### 1.1 「请求不等全仓」→ 限定为「不阻塞等待全量收尾;冷窗结果晚到仍在」

- **原表述位置**:docs/perf/2026-final-report.md §4 验收表 #5
  (「U1 冷启动 Definition 首查 475.34 ms 不等 30,001 文件全量…通过」);
  docs/architecture/current-state.md AUDIT-003(「PR5 后首扫已后台化:Definition 首查不等全仓扫描」)。
- **保留的事实**:U1 服务层口径 475.34ms(d4fd634)——首查在扫描继续推进时即返回,
  不等待全量收尾;该机制事实不变。
- **纠正(现场口径)**:真实编辑器联合场冷首查 **1189.08ms**(P0-4c §2,与 Kode-only
  1197ms 持平),其中 python-index-scan 本体 ~1,051ms(5044 文件)——冷窗内请求的
  **结果**仍要等首扫到位才齐(3 目标含扫描期类),不是「不等」。精确结论:
  **机制不阻塞等全量收尾;冷窗结果到达时间 ≈ 首扫时长;热态(稳态 P95 ≤4.10ms)不等**。
- 泛化句「不等全仓」按此限定改写,历史数字保留。

### 1.2 「后台不抢主线程」→ 限定为「Kode 面有契约+门禁;无条件结论不成立」

- **保留的事实**:P0 批三件——①平方级遍历锁(bucketReads===2,000 线性,
  tests/pythonIndexMaintenance.test.ts:19)②首扫批间 RequestLocal 执行
  (tests/entityMappingDeferredStartup.test.ts:150)③同步阻塞后定时器契约
  (tests/perf/timerDelay.bench.ts + tests/hoverBudget.test.ts:130)。
- **纠正(现场口径)**:Kode 在场时事件循环 P50/P95/P99=20.2/20.8/26.5ms,与
  Pylance-only(20.2/20.8/29.7ms)及裸面(20.2/21.2/33.2ms)无实质差异;突发 20 路
  并发前后宿主 P99 无堆积。但「后台不抢主线程」作为**无条件**结论不成立:任何扩展的
  冷启动工作都能推高单发延迟——联合场观测 max=815ms 单发尖峰,Pylance-only 对照场
  同有 617ms(归因 Python LS 冷索引,非 Kode;P0-4c §6.2)。Kode 自身阻塞面靠
  契约+门禁维持,不靠「不会发生」。
- 结论表述统一为:「Kode 后台任务分块让路、请求独占预算取消传播,由门禁锁定;
  事件循环分位与裸面无差;单发尖峰可来自同场其他扩展(Pylance 冷索引),非 Kode 独责」。

### 1.3 「超时已根治」→ 纠正为「无此宣称;契约=阻塞后首检查点收敛」

- **核查**:仓库源文档无「超时已根治」字面表述(grep 全 docs 无命中);该说法属
  口头/印象泛化。如实口径:P0-4a 固化的是**契约**——10ms 预算遇 150ms 同步阻塞,
  linked token 在阻塞后首个检查点收敛(T2:1,000/1,000,000 ops 即停),
  timerDelay=140.76ms 是**测量值**不是「已消除」;hoverBudget 契约由门禁锁定。
- 现场佐证:热态 hover 稳态 P95 ≤5.05ms(目标 30ms),暖机窗 71.29ms 单列——
  超时预算机制工作正常,但暖机窗尾部仍在(主体为 Pylance 冷分析+派发,P0-4c §6.1)。
- 结论:**没有任何「根治」宣称需要维护;报告只主张契约存在且被测试锁定**。
