## 实现(semantics/cell.rs,新模块)

**引擎事实**(设计文档 §2,kbe/src/server/baseapp/entity.cpp:238/250
`Entity::createCellData`,设计期已核实):

- **有 Cell 部件才创建**:无 cell 域属性 + 无 cell 方法 + 无组件槽 →
  `CellDataStatus::NoCellPart`,字段表恒空 + `no-cell-part` 判定事实
  (引擎不建 cellData,不伪造字段);
- **字段取 Cell 属性描述**:域位真值 = `kode_parser::model::flag_domains`
  (common.h 真值表,含 KR-AUD-87 OWN_CLIENT/OTHER_CLIENTS);Flags 未配置
  → 空域位 → 不进字段表(与 TS「无域位可判,不发明」同口径);
- **组件另建 Cell 数据**:组件槽登记进 `component_slots`(槽在即
  cellData 有嵌套面 → 不判「无部件」),递归展开归 CELL-03;
- **内建键不在本批**:position/direction 归 CELL-02 独立引擎来源。

**继承/接口展开**:复用 BAS-05 `EntitySnapshot`(展开序自身→父链→接口;
同名多来源进 conflicts 不任取)。snapshot 的 `PropertyView` 增 `domains`
域位面(flag_domains 真值,cell.rs 与后续 CELL 批次共用),cell.rs 只按
`domains.contains("cell")` 过滤。

**缺 Cell 脚本状态**(KR-AUD-74 布局:引擎按 `scripts/cell/<Name>.py`
装载):`ScriptUniverse` trait 由调用方供工作区已知脚本集(引擎不重读盘);
`ScriptNameSet` 为最简实现。四态互斥:

| 状态 | 条件 |
| --- | --- |
| `Ready` | 有 Cell 部件 + cell 脚本在 |
| `CellScriptMissing` | 有 Cell 部件 + 脚本宇宙判缺(`missing-cell-script:<Name>` 事实) |
| `NoCellPart` | 无任何 cell 面(引擎不建 cellData) |
| `ScriptUnknown` | 脚本宇宙未提供(诚实,不猜存在与否) |

- **组件槽只登记不展开**:槽内字段属 CELL-03(其验收「仅纳入组件 Cell 侧
