## 根因:win32 魔数守门结构拒收一切真 PE

`src/backend/nativeBinary.ts` 的 `matchesPlatformFormat`:
`readHeaderHex` 读**首 4 字节**转 hex(真 PE = `4d5a9000`,8 个 hex 字符),
而 `expectedMagics('win32')` 返回 `['4d5a']`(2 字节,4 个 hex 字符),
精确比对**永不相等** → Windows 上每个真 PE 都被判「平台不匹配」拒收 →
serverPath 恒空 → `serveFromRust()` 恒 false → 全部回落 TS、零 spawn。
linux ELF(`7f454c46` 恰 4 字节)与 darwin(8 hex 魔数)结构上恰好自洽,
唯独 win32 必坏——即 nightly win32 包在真机「找不到 bin」的全部根因。

测试长期没抓到:`tests/nativeBinary.test.ts` 的 win32 fixture 用
`Buffer.from('4d5a','hex')`(**2 字节文件**)——4 字节读盘从 2 字节文件只能
读到 2 字节,hex 恰为 `4d5a`,假阴闭环。真 PE(≥4 字节)从未进过 fixture。

修复(a7b96022):比对改前缀语义
`expectedMagics(platform).some(magic => header.startsWith(magic))`;fixture
换真 PE 形状 `4d5a9000` 并新增回归钉(KODE-WINPKG-001 命名用例:真 4 字节
PE 命中 + rejectedReason null;截断 2 字节 MZ 仍命中;ELF 落 win32 仍拒收)。
prove-red:回退 src 修复跑新用例,2 failed,复纳后全绿
(nativeBinary 9 + nativeSmokeRetry 5 + coreRediscover 5,tsc/eslint 零红)。

## 判例

- **跨平台魔数闸:头读 N 字节、期望 M 字节时精确比对是结构 bug**——读宽
  与魔数宽不一致的平台(win32 MZ=2B)整类拒收;比对语义必须与读宽解耦
  (前缀语义)。fixture 必须用**真实产品形状**(真 PE 4 字节头),2 字节
  假件会与读宽巧合自洽形成假阴闭环。
- **「进程不存在」归因链**:先证 config 面(probe 读配置)→ 在位面
  (sha/magic)→ 可执行面(exthost 内直接 spawn)→ 运行门 mode(QuickPick
  动作表解码)→ 生命周期通道(零行 = 零尝试);层层收窄后剩下的唯一臂
  即真因,勿跳步改码。
- **状态栏/浮窗真机取证**:exthost 内 spawn PowerShell 跑截图脚本保证同
  交互会话;PrintWindow 对 Chromium 视口渲染可能吞状态栏条,全屏
  CopyFromScreen 同会话更可靠;`showInformationMessage` 按 per-extension
  API 实例分发,exthost 内 monkey-patch 拦不到他扩展的消息。
- 打包产物取**干净 worktree**(HEAD 的 tsc+bundle),共树在途改动零携带;
  `write-build-commit.mjs` 后 bin/manifest.commit 必须与
  out/buildCommit.json 对齐(身份校验双查)。
