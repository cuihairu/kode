# KBUG-GATE hover 预检吞 Rust 可支持形态 —— 修复纪实(2026-11-12)

账本:`todo.md` KBUG-GATE 组(审计基线 `10f4b85e`)。缺陷 = 生产入口
`hover.ts` 预检用 TS「单层调用」正则(`parseLocalAssignmentCall`)代替
Rust 形态判定:`x = alias`(别名链)与 `x = build().load()`(链式调用)
在 TS 侧判得「无候选」→ Rust localReturnType 根本收不到查询,而 Rust 引擎
本身已支持这两类形态(RhsShape::Local 别名递归 / CalleeShape::Chained)。

## 缺陷定位(修前)

- `src/languageProviders/hover.ts:385` 预检闸
  `matchingAssignments(docLines, position.line, word).length > 0`:
  matchingAssignments 只在最近写点 RHS 为单层/属性调用时产出候选,
  别名/链式/常量等形态返回 `[]` → 闸关闭 → 零 RPC;
- `src/backend/pythonReturnTypeInference.ts:matchingAssignments`:掩码 +
  作用域上扫 + 形态过滤三职责耦合在一函数,hover 预检误用其形态过滤
  当存在性判定(职责越位 = 双侧漂移温床)。

## 修复

1. **扫描单一实现(GATE-03)**:抽 `nearestSameNameWrite`(私有)——
   掩码(KR-AUD-64 跨行三引号)+ 作用域上扫(IDE-HOV-016 def/class
   头缩进闸)+ 最近写点(IDE-AUD-042),TS 链(matchingAssignments)与
   hover 预检(hasLocalReturnCandidate)共用,两侧永不各自漂移;
2. **预检存在性口径(GATE-01/02)**:新导出
   `hasLocalReturnCandidate(lines, hoverLine, word)` = 作用域内有同名
   写点即放行;形态可推导性与答案诚实性归 Rust 裁定。只排除可证明
   无结果:字符串/注释伪赋值(掩码)、空词/行越界、作用域内无同名写点;
   不在 TS 复制 Rust 的 RHS 形态判定(常量/字面量写点放行后由 Rust
   诚实答 null);
3. **hover.ts 闸换面**:预检调 `hasLocalReturnCandidate`;
   `matchingAssignments` 保留原调用形态语义专供 TS 链
   (resolveLocalVariableReturnType / …FromSnapshot),语义逐字节不变
   (同扫描 + 同 `parseLocalAssignmentCall` 过滤,仅解耦);
4. **调用点收敛**:hover.ts 对 matchingAssignments 的引用清零
   (import 换名),TS 链两调用点不动。

## 边界(诚实记录)

- **写点悬停异步化**:同名写点存在(含常量/字面量)的悬停从同步 null
  变为「1 次 Rust 查询(诚实空)+ TS 链 + 1 次下游重入」的异步 null
  ——不显伪类型不变,交互预算(LOCAL_RETURN_RUST_BUDGET_MS=2000)
  封顶;这是不在 TS 克隆形态判定的代价,由 Rust 契约演进吃掉
  (若 Rust 未来从字面量推导注解,预检无需再改);
- 预检上扫以「行首目标」为写点判据(`ASSIGNMENT_PATTERN` 锚定行首,
  天然排除 `f(x=1)` 关键字实参伪写);链式多目标的第二目标
  (`x = y = make()` 悬 y)不在锚定判据内,仍保守跳过(与 TS 链同域
  口径,非本批账本缺陷,未扩权);
- TS 链调用形态语义(matchingAssignments)逐字节保留:杀开关兜底
  路径(kbengine.core.backend=ts)行为不变;
- 循环回边下方写点(悬停行之上无写点、下方有)仍不可见——上扫预检
  与 Rust 保守折叠的既知差异,非本批引入。
