## 实现(设计 §4「增量」:语义快照带版本,查询不等全仓重扫)

文档 overlay 与版本语义由 `kode_vfs::store::DocumentStore`(VFS-003)
承载——本模块**不重造**,在其上提供语义事实的版本化快照库:

- **`SnapshotStore<T>`**:每文档至多一槽 `(version, facts)`;`commit` 拒绝
  过期构建(版本 < 槽版本,现有保留),接受新版本与同版本幂等重算;
  `get` 查询即当前槽(不重扫);`version_of` 取当前版本;`remove` 清槽
  并返回被清事实(删除/重开清理 + 下游失效传播);`clear` 工程关闭全清;
  `fold` = 工程代数(键升序确定性折叠,组合子调用方给)。
- **`Build<T>`**:构建产物(事实 + 计算所依据的文档版本)。版本来源契约
  如实:打开文档用 VFS overlay 版本(与 VFS-003 同源严格递增);磁盘文档
  VFS 版本为 None → 调用方给定统一基线(如 0),保证过期磁盘构建同样被拒。
- **`ProjectDefResolver<'a>`**:工程代数的具体面——实现
  `super::snapshot::DefResolver`,跨全部文档槽按类型名解析 def;类型名
  派生规则 = **def 文件名去扩展名(KBEngine 约定,大小写敏感)**,
  `def_name_from_key` 显式实现并测试;多槽同名解析序 = 文档键升序
  (确定性,取首个;冲突裁决由 snapshot 层 conflicts 记录承担,此处不任取)。

## 验收(BAS-08 四点全)

| 验收点 | 测试 |
| --- | --- |
| 查询使用文档 overlay 和工程代数 | overlay 由 VFS-003 承载(模块头如实声明);工程视图 = fold 确定性折叠(fold_composes_deterministically 键升序断言) + ProjectDefResolver 跨文档解析(project_resolver_resolves_across_docs) |
| 过期构建不得覆盖新版本 | stale_build_rejected_keeps_current(v2 提交后 v1 构建 → Stale,get 仍 v2);同版本重算接受(equal_version_recompute_accepted) |
| 删除/重开文档清理对应事实 | remove_clears_slot_and_returns_facts(清槽返回被清事实;重开提交不残留) + clear_empties_all |
| (配套)版本与事实可查 | commit_then_get_returns_facts + version_of + len/is_empty |

测试 9 例。**版本基线语义(边界如实)**:打开/磁盘两来源由 VFS 版本契约
承载,本模块不做「文档文本 → 版本」推导,版本是构建方输入,不伪造。

## 边界与诚实记录

- **无 RPC 面**:纯库模块,消费边界待 BAS-10(共享查询契约)接线;
- **版本不伪造**:磁盘文档无 VFS 版本时基线由调用方定(契约如实记录,

  snapshot 层 conflicts(与 BAS-05 同一纪律);
